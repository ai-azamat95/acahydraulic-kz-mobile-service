## Поведение каталога

На GitHub Pages запрос `?page=2` не выбирает отдельный HTML-файл. Поэтому исправление вводит настоящие статические адреса, а не только другой canonical:

| Коллекция | Начало | Следующая страница |
|---|---|---|
| Категория | `/catalog/category/gear-pumps/` | `/catalog/category/gear-pumps/page/2/` |
| Бренд | `/catalog/brand/komatsu/` | `/catalog/brand/komatsu/page/2/` |
| Модель | `/catalog/model/pc200-8/` | `/catalog/model/pc200-8/page/2/` |
| Все товары | `/catalog/page/1/` | `/catalog/page/2/` |

`/catalog/` остаётся выбором категорий и получает ссылку «Все товары каталога». Старые карточки, категории, бренды и модели сохраняют адреса.

- Каждая новая страница содержит соответствующие десять товаров, реальные ссылки на соседние страницы и собственный canonical в исходном HTML.
- Генератор использует тот же опубликованный полный индекс и индексы категорий, что браузер. Их порядок отличается от порядка JSON-чанков; это проверено сравнением HTML с реальным DOM.
- Позиции ItemList учитывают номер страницы. Названия моделей и номер страницы сохраняются после сокращения title, поэтому новые страницы не получают одинаковые заголовки.
- В sitemap включены все 4 172 страницы коллекций и пагинации. Это продолжение существующих списков, а не новые коммерческие посадочные по ключевым словам.
- Старые ссылки с `?page=2` при включённом JavaScript нормализуются через replace-навигацию; UTM, gclid и hash сохраняются. Некорректный query-номер нормализуется, слишком большой старый номер переходит к последней странице.
- Невалидные новые статические адреса не генерируются: хостинг отвечает HTTP 404, браузер показывает неиндексируемую страницу ошибки.
- Поиск и уточнения остаются динамическими и неиндексируемыми. Подбор категории внутри бренда не заменяет контекст бренда.

**Ограничение совместимости:** без JavaScript старый `?page=N` по-прежнему получает базовый файл статического хостинга. В нём есть явное пояснение и ссылки на настоящие страницы. HTTP-редирект по query требует поддержки на стороне хостинга; такой поддержки в GitHub Pages нет. Новые ссылки работают без JavaScript.

Все 12 293 записи сохранены, включая 152 турбокомпрессора из PR №188. Данные товаров, цены, характеристики и совместимость этим изменением не редактировались. Проверяется отсутствие пропусков/повторных ID между страницами каждой коллекции, без объединения разных записей по совпавшему OEM.

## Уведомление cookie

- На мобильных и средних экранах первое уведомление находится в потоке документа и не закрывает CTA. При 390×844 его высота составляет 194 px вместо наблюдавшихся на production 366 px; при 320 px — 214 px.
- На экранах от 1280 px применяется компактное окно справа, которое не перекрывает основные действия главной.
- Сохранены три действия: только обязательные, принять все, настройка отдельных категорий. Проверены аналитика отдельно, реклама отдельно, оба разрешения, сохранение после reload, повторное открытие и отзыв.
- До выбора пользователя запросы SDK аналитики/рекламы не появляются. Формат сохранённого согласия, сроки и функции применения разрешений не менялись.
- Телефон, WhatsApp, формы и код учёта PR №187 сохранены. У его локального верификатора добавлены только путь к установленному Chrome и отдельный каталог артефактов.

## Как воспроизвести

Перед сборкой выполнить `node scripts/prepare-public-catalog.mjs`, затем штатный build и генераторы из `.github/workflows/pages.yml`. Проверить `node --test --test-concurrency=1 tests/*.test.mjs`, `pnpm check`, `pnpm exec vitest run --pool=threads --poolOptions.threads.singleThread` и `python3 scripts/audit-seo.py dist/public --strict`.

Локальный браузерный тест: `scripts/check-seo-pagination-browser.mjs`. Переменная `ACA_PLAYWRIGHT_PATH` задаёт установленный Playwright, `ACA_CHROME_EXECUTABLE` — установленный Chrome. Загрузка браузеров на Mac не нужна. В CI используется имеющийся runtime браузерного workflow.

Артефакт CI `seo-pagination-cookie-check` содержит `browser-checks.json`, отчёт телефонного теста, скриншоты `cookie-initial-390.png`, `cookie-initial-1440.png`, `cookie-settings-390.png`, `gear-page-2-no-js.png`, `gear-page-2-390.png`, `repair-form-390.png`. Локально они находятся в `output/seo-pagination-cookie/`.
